# Linux architecture

The `linux/` application is separate from the WinUI host. The portable JSON document retains launcher IDs, recursive items, and Windows settings. Unknown properties survive Linux edits. Shortcut launchers have whole-launcher Platform ownership: foreign launchers remain listed but disabled, with no item-level classification or filtering. Untagged legacy shortcut launchers belong to Windows; web launchers remain shared. Concurrent file changes reject stale saves rather than overwrite another writer.

`little_launcher/document.py` owns validation and visibility; `storage.py` owns atomic private writes; `controller.py` owns GUI transactions. Native Qt Widgets provide Settings, item editing, and shortcut flyouts. `catalog.py` and `app_picker.py` own the XDG application catalog and native chooser. `desktop.py` owns XDG integration, desktop theme monitoring, and shell-free launching. `icons.py` owns native and SNI icon rendering. `tray.py` exports one StatusNotifierItem and native desktop menu per launcher through private D-Bus connections. Host activation coordinates are passed to the optional, app-owned KWin script before first presentation. The script is scoped by application ID and protocol caption, and does not reposition on activation.

`app.py` centralizes launcher routing, application lifetime, private single-instance signaling, and tray ownership. `forms.py`, `editor.py`, `flyout.py`, and `settings.py` use the desktop's actual Qt style, palette, and fonts. `item_geometry.py` computes Qt-independent Windows-reference layout; `items_view.py` hosts intrinsic item/column geometry in both windows. `item_button.py` paints native cells with fixed content slots, two-line large-icon labels and non-reflowing hover controls. `item_drag.py` owns session-bound drag decoding and invisible empty collection targets. `item_editing.py` owns immediate full-source commands for both hosts. `item_toolbar.py` owns natural-width regular actions and compact 32-pixel toolbar slots. The regular editor immediately commits the complete recursive source tree, including hidden rows, and ends with Done. It never serializes a filtered presentation. Rebuilds invalidate internal drag tokens. Read-only shared subscribers cannot edit items or bookmark content.

Web launchers use a separate current Electron process through `browser.py`, with sandboxed remote views and persistent local-only sessions. The inherited input/output pipes are the only parent control transport. Qt's actual desktop palette and font are passed to trusted local browser chrome. Remote pages receive no preload or Node integration. `browser/profiles.cjs` owns permissions and local partitions; `lifecycle.cjs` owns hidden-page protection and sleep; `window.cjs` owns browser windows and trusted chrome. `WebHomeUrl` remains separate from saved bookmarks. The footer supports folders and adding the current page through a native Qt dialog. `bookmark_tree.py` owns Qt-independent saved-tree mutations; `bookmarks.py` owns native edit/rename/add/remove prompts and transactional saves. `browser/bookmarks.cjs` owns the display projection and desktop edit menus. Saved source paths and a full-tree render revision bind menu actions to the content actually clicked. Native dialogs also compare the launcher preimage at save time. Unknown bookmark metadata, unrendered entries and independent home state survive edits, reorder and cross-folder moves. Empty folders remain visible; nested entries are editable through the folder context menu’s Edit contents submenu. Native dialog replies return focus to the existing web window without remapping it. Desktop theme changes reach existing browser chrome without navigating its page. Camera/microphone grants conservatively protect the page until navigation or reload because Electron does not expose an exact capture-ended signal. The Wayland screen-capture path opens the real KDE PipeWire source picker and preserves its parent. The original GPU-free QPainter fixture could not stream. The isolated Fedora 44 OpenGL fixture now verifies two received portal video frames and quit protection on Plasma 6.7.5; physical-session capture acceptance remains separate. OneDrive personal-account sync is implemented for testing; other provider and shared-launcher gates remain unfinished. Distro QtWebEngine is retained only in the qualification fixture because its observed Chromium version is too old for this application's browser host.

The development desktop is isolated in Docker with a private D-Bus session and nested KWin Wayland compositor. It does not use the host display or bus. Production readiness requires integrated runtime checks, packaging, Windows compatibility, sync qualification, and the agreed lifecycle protections. Source scaffolding alone does not establish those gates.

The KWin helper dismisses unpinned web flyouts on a foreign activation, preserving transient ownership and native Qt permission dialogs. Focus changes never reposition an existing parent. Physical desktop and portal behavior remain separate acceptance gates. Native shortcut popup surfaces use the active Qt menu primitive with translucent backing, rather than fixed CSS corners. The scroll widget must explicitly disable autofill after QScrollArea.setWidget, which otherwise covers those native corners. Normal list rows are 32 pixels; large cells are 80 × 84 and small cells 40 × 40. Groups are plain section headers, with narrow icon groups packed beside each other. Columns have no extra gap beyond the reference chrome. The regular editor has 24-pixel body side/bottom padding, a compact intrinsic preview in a two-axis viewport, a separate settings control and external Done. The flyout pencil enters editing in the same window with an owned floating toolbar; Done returns to normal and Escape first ends editing, then dismisses. Editing never changes item sizes. The toolbar uses compositor placement, follows owner resizing and returns focus to the owner. Explicit content-size changes retain the original activation edge; focus transitions never reposition the body.

The Fedora development fixture uses `Dockerfile.fedora`, `launch-fedora.sh`, and a virtual KWin output with an explicitly passed render node. It has no host display, bus or home mounts. `private_input.py` and `capture_wayland.py` operate only on its private compositor, using fixture-only interpreter grants. Production uses neither test-input nor screenshot privileges. KDE tool discovery checks PATH and the distro Qt binaries directory.

`dev/preview_desktop.py` is an explicitly authorized real-desktop preview, distinct from the private fixture. It uses disposable data, disables machine-setup controls and does not install the KWin helper or change autostart. Its sample links open in isolated app windows. An optional --temporary-integration flag requires separate explicit authorization. It loads only a scoped copy for unique preview Qt/Electron identities and the current launcher IDs, writes no installed helper or kwinrc preference, and unloads on normal preview quit. Live startup, physical tray behavior, user visual approval and anchored placement are separate evidence gates.

The KWin helper now follows the Windows panel/overflow policy instead of choosing the nearest edge: reserved vertical sides take precedence, horizontal panel corners remain horizontal and interior tray overflow activations open above their actual coordinates. Only shortcut content resizing is re-anchored; web maximize/user resizing is left to KWin. `dev/verify_placement.py` observes a single private test window's actual compositor frame.

`browser/window.cjs` owns a collection of remote tabs and keeps `view` as the active view alias. Each tab has its own `PageLifecycle`; `main.cjs` binds permission/upload/download callbacks to their originating tab and aggregates interruption checks across all tabs. Target-blank/new-window contents are adopted through Electron's supplied WebContents with sandbox/context isolation/no remote preload enforced. Background tabs retain their source identity and cannot navigate the previously active page. Closed/unloaded views distinguish delayed destruction from their replacement. `lifecycle.cjs` serializes CDP transitions to avoid late freeze replies leaving reopened pages frozen. `browser/web_actions.cjs` owns trusted native menus and keyboard actions. Chrome uses Windows-reference 34-pixel rows, actual navigation state, address and tab controls and bookmark overflow. Quick preferences are allowlisted typed Boolean/integer fields saved by the native controller, never by remote pages.

`ApplicationList` in `app_picker.py` is reusable inside the item editor's Apps & web apps/File or link tabs and standalone picker. Item fields share one pending target/name/icon/OS state. Launcher settings use native collapsible destinations in the same order as web menus, with Behavior and Privacy initially collapsed. Item Move to actions offer real groups, top level and other writable shortcut launchers; cross-launcher moves are one guarded full-document transaction. Source-view guards reject stale menu paths. [The parity review](linux-ui-parity.md) records remaining gaps; these changes do not establish full Windows UI parity.

Plasma Wayland SNI coordinates are native pixels by default (`kdeglobals`, KScreen/XwaylandClientsScale). `desktop.native_tray_coordinates` reads that choice; only tray-origin anchors carry `:native` through Qt/Electron titles. KWin converts them using each output's actual devicePixelRatio before placement. Do not divide by QScreen.devicePixelRatio: Qt Widgets can report a rounded buffer ratio (2 on the observed 150% output). Settings/fixture anchors already in logical coordinates stay unmarked. The private 150% observer verifies this path; mixed-scale/multiple-output physical qualification remains open. Passive Settings navigation/list/scroll frames and the editor preview frame are disabled to avoid broad Breeze hover outlines; actionable native feedback remains.

`launcher_card.py` owns the Settings launcher card's native passive frame,450px preferred column and two-line trailing-chevron actions. `settings.py` now follows Windows `LaunchersPage`: whole-page scrolling, left Add Launcher, icon/name header with24px move/delete controls, divider, Settings row, then Items with a separate40px bulk button. Card padding16 and inter-row/card spacing8 follow source geometry; action rows use14/12px native-font text with12/10 padding. No separate Open row or header ellipsis is introduced. Native hover/focus belongs to actionable rows/buttons, not the passive card frame. Item counts recurse through groups and skip column breaks. Per-launcher JSON bulk export retains every item; validated Replace/Append import commits with a stale-state check and controller read-only enforcement. Sharing/browser bookmark import and other Settings page coverage remain explicitly unfinished.

`launcher_settings.py` now owns `LauncherDialog`, `SettingsRow` and `SectionHeader`, re-exported by `forms.py` for compatibility. Launcher-only settings use the560px reference width,24/8/24/24 body padding,12px row/section spacing,14/12px label/subtitle, right-aligned natural-height controls and a stacked URL. Native expanders have left labels/right arrows without painting an expanded section as a selected button. A single Done footer, Escape and close finish the form. Production dialogs now commit completed controls immediately with a full-launcher preimage guard; successful saves advance that preimage and external changes stop stale editing. Standalone fixture forms without a controller still return a staged value. Type and policy changes only reveal applicable rows and preserve saved content/unknown fields; changing a shortcut launcher to web closes its regular item editor. Item/bookmark dialogs keep separate Save/Cancel behavior.

Shortcut protocol titles now carry `:owned` during editing, menus and owned settings. KWin focuses newly mapped native shortcut flyouts once and applies its existing foreign-activation dismissal to them as a fallback for Qt deactivation. Caption changes only re-evaluate ownership/dismissal; they never reposition a returning parent. `dev/verify_shortcut_dismissal.py` tests real private input against a separate foreground process. Both baseline and fixed flows passed in that fixture, so it establishes covered behavior rather than exact reproduction of the physical-session report.

`LauncherGeometry.groups` contains `GroupPlacement` full-container bounds, and `group_drop_zone` holds the Qt-independent8px outer-band policy. `items_view.py` creates `ItemGroup` widgets with real header/child parenting; `item_group.py` centralizes full-bounds hit testing and passive `GroupOverlay` feedback. Child and header drag events delegate to that container. Groups reorder against another group's full midpoint and never nest; non-group interior drops resolve child slots or append, while outer bands insert a root sibling. Full source paths retain hidden members. Header/blank-space drag handles move the complete group. Native drag cards identify group/count; the verified Wayland build does not update their visible text during QDrag.exec, so dynamic destination text remains a documented gap while in-view cues update.

Native Done can follow an app switch while the floating toolbar does not activate. The shortcut host marks a one-shot `:focus` request while keeping the owned flag until WindowActivate acknowledges it; the KWin caption watcher restores that owner once, without moving it. This prevents an inactive restored popup from missing the next click-away. `dev/compositor_probe.py` records only named QA windows in the private compositor so native input uses real client coordinates, not Wayland's non-authoritative mapToGlobal values. `verify_group_drag.py` exercises all modes/hosts; `verify_shortcut_dismissal.py` covers the full foreign-click/edit/Done/next-click cycle.
