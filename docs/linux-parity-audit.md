## Linux site permissions and extensions

`browser/permission_store.cjs` atomically stores versioned notification allow/deny decisions in `browser/site-permissions.json`, keyed by stable private/shared profile identity and exact HTTP(S) origin. The app version/path is not a key. Malformed/oversized/symlinked files are preserved and cannot be overwritten. Media/camera/microphone/screen grants remain transient. Reset permissions and clear browsing data explicitly clear the selected profile’s stored notification choices. Existing in-memory approvals cannot be recovered; the first approval after installing this change will persist through subsequent restarts/updates.

`browser/extension_host.cjs` manages device-local code choices in `browser/extension-catalog.json` and managed packages under `browser/extensions/packages/`. Its native management dialog is `extensions_page.py`, opened from System or each web launcher’s More → Extensions menu; the same menu opens extension popups. `extension_packages.py` verifies a pinned official Bitwarden GitHub browser ZIP against its size/SHA256 and extracts it with bounded file/count/expanded-size checks, rejecting traversal, symlinks and duplicate paths. Folder import makes a private managed copy. Adding an extension shows its requested permissions before enabling. No vault login or credentials are imported.

Extension code is enabled across the app, but storage, sign-ins and vaults stay in each launcher’s private/shared browser session. Enabled extensions restore before first ordinary page navigation; disabling/removing stops their runtime and closes owned popups. Removing the last launcher using a profile suspends that profile’s extension runtime; re-enabling restores it. Browser page views register through `extension_registry.cjs`; tabs, frames and popup ownership expose only those registered remote views, never trusted local chrome.
