# Store assets

| Folder | Holds |
| --- | --- |
| `microsoft/listings.json`, `listings.md` | The Store listing text in every locale, and the claims it makes (see `listings.md`) |
| `manifest.json` | Every Store screenshot in listing order: its raw source, theme, crop, en-US caption and alt text (LIST-8); `{locale}` in a path stands for each listing locale |
| `raw/microsoft/<locale>/` | The raw captures, one folder per listing locale: the test VM's whole desktop at 200% display scale, each with the `.json` sidecar the capture helper writes |
| `microsoft/screenshots/<locale>/` | The listing screenshots, rendered from that locale's raw captures, with the generated first screenshot (`00-hero-dark.png`) |
| `microsoft/text-free/` | The hero's one text-free copy, drawn from the en-US capture, for a web page |
| `capture/` | The capture scripts, the synthetic settings (`seed-settings.json`) and each language's names for them (`sample-data.json`) |
| `web/screenshots/` | The README's screenshots; a separate set, never uploaded to the Store |

## Screenshots

Captured from the real installed app with synthetic settings, never from a personal machine (LIST-8). Every listing language has its own set, fully localized: Windows itself, the app and the sample data (launcher, item, group and website names) are all in that language (en-CA and fr-CA reuse en-US and fr-FR). Captures are taken on a 1920 x 1080 desktop at 200% display scale (3840 x 2160), which the renderer reduces to the Store size. Every shot is in dark mode on the Windows 11 dark wallpaper (`img19.jpg`). The captions in `manifest.json` are the en-US `screenshotCaptions` in `listings.json`, in the same order and count; each other locale has its own translation there. The maintainer approves a new or changed set from the English screenshots and one sample language before it is committed; the other languages must pass the automated checks.

The synthetic settings hold themed launchers, each with its own colored glyph tray icon: Everyday (Store apps), Admin tools, Creative (two groups), Web (two groups of sites) and a YouTube web launcher showing Big Buck Bunny (CC BY, on Blender's official channel). Shot 00 is the generated hero (below). Shots 01 to 06 show a tray flyout or the taskbar and use the `tray` crop; 07 and 08 are Settings windows and use the default `window` crop.

1. **Prepare** the Windows 11 test VM with the windows-build-tools app-test helpers, one language at a time. Switch Windows to the language first (`app_test_language <locale>`, then a cold cycle, since it applies at sign-in), install a dev package, run `screenshot-desktop.ps1 -Mode Prepare -Scale 200` (dark mode, a 1920 x 1080 desktop at 200%, the dark wallpaper, window effects on, notifications off), hide the desktop icons, tidy the taskbar and turn search and Widgets off.
2. **Capture** with `capture/capture.sh <locale>` from this repo's root. It runs `capture/capture.ps1` in the desktop session, which writes `capture/seed-settings.json` as the app's settings with every name replaced by the locale's from `capture/sample-data.json` and the app's language set to the locale, sets the guest clock to Eastern time, opens each flyout or window (controls by automation ID, tray icons by launcher name), and saves the whole desktop with `Save-DesktopCapture`. Pinning a launcher to the taskbar raises a Windows prompt that UI Automation cannot see; the script answers it by position. The script then copies the captures into `raw/microsoft/<locale>/` under the manifest's names. `CAPTURE_PREPARE_LOCALE` can name a command that switches the language, so one `capture/capture.sh` run loops over every listing language. The names of Windows' own apps in `sample-data.json` must match what Windows shows in that language, so check them on each language's first capture. End the visit with `app_test_clean` and switch Windows back with `app_test_language en-US`.
3. **Render** with `npm run shots:render` (winui-app-kit's renderer; its README has the rules): each locale's captures are cropped to 1366 x 768 in logical pixels and each 2 x 2 block averaged, with nothing composited or shaved, and written without an alpha channel to `microsoft/screenshots/<locale>/` (ASSET-9). It renders nothing while any listing locale lacks a capture. Recaptioning needs no recapture; a new look does.
4. **Check** with `npm run check:screenshots` (part of `npm run validate`): every listing locale has every capture, each with its sidecar, taken dark, at 100% or 200% scale, with effects on and the dark wallpaper; every screenshot was written by the renderer at exactly 1366 x 768; the captions match the en-US `screenshotCaptions`; no stray file is present in a locale folder.
5. **Sync** with the next Store release: the Store workflow's `screenshots` input uploads every locale's set, its hero first, with that locale's captions from `listings.json`, and keeps the listing's logos. Check the draft in Partner Center before submitting it.

A UI change that shows in a screenshot means recapturing that shot.

## The first screenshot: a generated hero

Store search shows only the first screenshot, at about 320 x 180, so it is a generated hero (D-123): a rose panel with the icon, name, headline and subline, beside the real icon-view flyout from that locale's `raw/microsoft/<locale>/00-icons-dark.png`, enlarged whole. Each listing locale has its own, drawn from its `heroHeadline` and `heroSubline` in `listings.json`; en-CA and fr-CA use en-US's and fr-FR's. Its caption is the subline. `npm run hero` draws them (devkit, through winui-app-kit's `scripts/devkit`), and `npm run check:hero` in `validate` fails when one no longer matches its inputs or a listing locale has no capture. The text-free copy is drawn from the en-US capture. New or changed headlines are approved by the maintainer, like any screenshot.
