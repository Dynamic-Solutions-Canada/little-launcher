# Native launcher editing checks

These scripts exercise the real installed WinUI application on a dedicated disposable Windows desktop. They move its pointer, restart the matching Developer package between cases, and temporarily replace its settings with synthetic data. They require an explicit expected computer name and desktop-interaction opt-in. They must run in that computer's signed-in interactive session, with one monitor and English app text.

The default run covers eight gestures in each of list, large-icon and small-icon modes, using the regular editor and dark theme. Regular setup explicitly opens App Settings through the app-deployed physical companion before navigating to the editor, so a previously hidden Settings window cannot block setup. `HostMode=native` uses the same companion's edit-items action to open the actual tray flyout. Both wait for the package's `RoamingState\LittleLauncher` deployment, verify the main-executable breadcrumb and the companion's SHA-256 against the intended installed package, and record them in each case's `-companion.json`. They do not execute the protected WindowsApps copy or deploy a helper themselves. `Theme=1` selects light theme; `Theme=2` selects dark. Each case starts fresh and verifies saved ordering, complete original item inventory, one column boundary and no nested groups. It also holds the insertion position, compares the untouched target's UIA bounds before and during the drag, and saves the comparison. Source opacity is not part of that layout assertion. Child-reorder points stay inside the new outer group bands rather than implicitly using the bottom edge.

Optional follow-up cases use the same guarded entrypoint and fixture. Copy `interaction-cases.ps1` alongside the main script and executor; it is a dot-sourced part of the suite, not an independent desktop runner.

| `--cases` value | Actual interaction and assertion |
|---|---|
| `group-pencil` | Hover a real group, tap the drawn pencil at its DPI-scaled position, require the real Rename Group window, physically cancel, and verify saved items and geometry |
| `focus-return-done` | Switch to an isolated Notepad document, return through floating Done in native mode, click Notepad again, and require flyout dismissal; regular mode returns to its title bar and requires Done to close the editor |
| `focus-body-done` | Repeat with a physical body return before Done as the activation control |
| `preview-target-change` | Hold a child over a column, another group's child and the final group; capture expected hints and hit witnesses, then require the final destination order |
| `preview-target-cancel` | Repeat those changing targets, cancel with held Escape, and require unchanged saved items |
| `toolbar-settings` | Check the compact settings action, verify its regular top-right alignment at initial and narrower widths, then physically open and close Launcher Settings |
| `item-into-group-end` | Cross the inside/end and outside/after positions, then append inside; require the original top-level item to become the group's last child |
| `item-after-group` | Cross the same positions, then drop in the bottom edge band; require a top-level sibling immediately after the group with unchanged children |
| `child-after-own-group` | Extract a child through its own group's bottom edge band; require the same saved child as a sibling after its group |
| `item-before-group` | Drop a cross-column item in the top edge band; require a sibling before the group with unchanged children |
| `item-into-group-header` | Cross the inside/outside positions, then drop on the real header; require append inside the group |
| `group-boundary-cancel` | Cross inside, after and inside again, then cancel with held Escape; require unchanged saved items and review that tint/fade/carets clear |
| `group-end-leave` | Cross the same targets, leave the group for an ordinary item, then cancel; require exact geometry restoration and review fade/caret cleanup |

Select these cases explicitly, for example `--host-mode native --modes 1 0 2 --cases group-pencil focus-return-done focus-body-done preview-target-change preview-target-cancel toolbar-settings`. The original eight defaults remain unchanged. Focus cases require no existing Notepad process so the suite never closes an unrelated document. It creates one synthetic file in the output directory and closes only that document's process. Regular focus checks position that owned document away from the return point and verify the actual UIA hit before the physical return click. Toolbar alignment compares the settings button with the existing footer Done right edge; outer UIA window rectangles include invisible resize borders and are not the body-padding reference.

Preview screenshots require human review of name/count legibility, the current destination and the hint above the helper. Expected body sizes in DIPs are small icons 128x28 for an item or 136x36 for a group, list 156x32 or 156x40, and large icons 176x44. Each adds a 20-DIP hint above a 4-DIP gap. A failed render uses guarded native caption/glyph feedback; that error fallback has the OS-controlled caption position. Pixel bounds, error injection and invalid-target rendering are not automatically asserted by the suite.

Select the seven group-boundary cases explicitly for each host and all three modes. They save DPI-scaled point/expected-cue receipts and capture inside/after/inside transitions during one gesture. At every waypoint and twice during a held final point, they require unchanged saved items and exactly unchanged receiver, final-child and following-group bounds. Cancellation and leave cases also compare restored bounds when the host remains open. The regular editor may close through its existing Escape accelerator; in that case a receipt records expected closure and no post-close geometry claim. Pre-Escape waypoint/held bounds and post-Escape saved-item assertions still apply. Review the inside group tint, clear upper portion of the final child, progressive fade toward the overlapping lower marker against the unchanged child and full-width marker outside the group. Empty groups have no child to fade. High contrast retains the explicit marker/outline/caption and omits the fade. Tint/fade pixels and marker geometry are not automatically asserted. External Explorer payload routing and theme/high-contrast rendering still need separate native checks.

The suite captures during/after screenshots, per-case input and focus preconditions, the loaded WinUI binary version, app event logs when present, `results.json` and `summary.json`. Screenshots support human review of the group outline, grip/pencil contrast and named drag preview; there are no automated pixel assertions. No high-contrast setting is changed or tested. Read-only launchers, lifetime/rebuild invalidation, accessibility, arbitrary screen/DPI configurations and live sync require separate checks. The policy suite in [LauncherItemReorder.Tests](../LauncherItemReorder.Tests/README.md) covers stale collections, item identity, synthetic wrappers and serialization without user data or Windows input.

The capture notification confirmed the real operation, but that run does not establish physical-input acceptance after Snipping Tool or identify a product root cause. Use the existing installed Python and PowerShell 7. The executor launches PowerShell with `CREATE_NO_WINDOW`. A raw PowerShell scheduled task can create a console and steal input even when `-WindowStyle Hidden` is supplied, which caused misleading drag failures during VM qualification. `SetCursorPos` alone also failed to deliver advancing XAML pointer points in that VM; the suite retains real native absolute mouse movement for the held trajectory.

Cancellation holds Escape for 150 ms before releasing the mouse and retains it through that release. It records both keys' held state and a screenshot, then releases Escape in `finally`. An immediate Escape key-down/key-up followed by mouse-up raced the tray host's native cancellation during qualification; a saved move from that sequence did not establish a product cancellation defect.

Copy this directory to the disposable VM, then register an interactive scheduled task from a setup session. The following example names the designated VM explicitly and runs one regular-editor case first. Adjust the two local paths, preserving the expected machine and opt-in. The task is local to that VM; registering or running it on another person's active desktop is not an acceptable substitute.

```powershell
$testDirectory = "$env:USERPROFILE\Development\native-drag"
$outputDirectory = "$env:USERPROFILE\Development\drag-results\regular-dark-smoke"
$pythonw = (Get-Command pythonw.exe).Source
$arguments = @(
    ('"{0}\run-hidden.py"' -f $testDirectory),
    '--expected-computer-name WINDOWS-DEV',
    '--allow-desktop-interaction',
    ('--settings-path "{0}\LittleLauncher\settings.json"' -f $env:APPDATA),
    ('--output-directory "{0}"' -f $outputDirectory),
    '--host-mode regular --theme 2 --modes 1 --cases child-reorder'
) -join ' '
$action = New-ScheduledTaskAction -Execute $pythonw -Argument $arguments
$principal = New-ScheduledTaskPrincipal -UserId ([Security.Principal.WindowsIdentity]::GetCurrent().Name) -LogonType Interactive -RunLevel Limited
Register-ScheduledTask -TaskName 'LittleLauncher Native Drag' -Action $action -Principal $principal -Force
Start-ScheduledTask -TaskName 'LittleLauncher Native Drag'
```

The executor's flags map directly to the PowerShell suite's guarded parameters. Omit `--modes` and `--cases` for all 24 default cases. Use `--host-mode native` for the tray host and `--theme 1` for light. Choose a new output directory for every run, because the original settings backup and prior evidence must not be overwritten. The executor writes a sibling `.host.log` with setup errors and the PowerShell exit status is the scheduled process exit status. On completion, inspect `summary.json`, all failures and their screenshots. Remove only the test task you created when finished.

Normal completion and caught failures stop the matching package, restore the previous settings file (or its absence), and end the temporary keep-awake request. The app remains stopped. Forced task termination, a VM shutdown, or an inability to stop the package can prevent restoration. The original `settings-before.json` backup is retained in the run directory for recovery; treat it as private and keep outputs outside version control. No installation, publisher change, dependency installation or update to tracked versions is performed by this suite.
