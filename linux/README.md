# Little Launcher for Linux

Little Launcher for Linux provides native Qt desktop controls and a sandboxed Electron web engine alongside the Windows app. Download the x64 AppImage from [GitHub Releases](https://github.com/Dynamic-Solutions-Canada/little-launcher/releases/latest). AppImage is the only Linux format, targeting Debian 12 / Ubuntu 24.04 LTS or newer. Make the downloaded file executable, then run it from a writable location where you want to keep it. About provides update checks and explicit download, install and restart; login startup defaults on and can be disabled in System.

KDE is the primary desktop target. System offers an optional KWin helper for anchored placement. GNOME needs a tray extension and uses regular windows where anchored integration is unavailable. OneDrive sign-in needs an available desktop Secret Service wallet. See [AppImage delivery](#linux-appimage-delivery) for runtime requirements and [the root README](../README.md#linux-desktop-support) for platform differences.

## Development

The agreed product requirements are in [the Linux design](../docs/linux-design.md); component ownership is in [the Linux architecture guide](../docs/linux.md). The sections below document development workflows and qualification history.

Native Qt Widgets supply Settings, shortcut flyouts, item editing, dialogs, desktop colors, fonts, controls, and popup surfaces. A separate Electron 45 process supplies the browser engine. The Windows layout reference remains authoritative: Settings defaults to 900 × 700 logical pixels, web launchers to 480 × 720, large icons to 80 × 84 cells, and small icons to 40 × 40 cells. Native decoration and desktop metrics can change the outer frame.

## Run and verify

The isolated development desktop is preferred. It never mounts the host display, session bus, home directory, or browser profiles. The original Debian fixture is GPU-free. The Fedora fixture accepts an explicitly selected GPU render device for portal streaming qualification; it never receives a primary DRM node or display control.

```bash
npm ci --prefix linux/browser
linux/dev/launch.sh
```

`launch.sh` prints the exact owned container and private evidence directory. Stop only that container when finished. To reuse an existing Electron distribution, set `LITTLE_LAUNCHER_ELECTRON_DIST` to its distribution directory before launching. The image uses distro Qt bindings and matching KDE integration plugins, avoiding mixed Qt ABIs.

Within that container:

```bash
docker exec CONTAINER /work/in-session.sh sh -c 'PYTHONPATH=/source/linux python3 -m unittest discover -s /source/linux/tests -v'
docker exec CONTAINER /work/in-session.sh python3 /source/linux/dev/verify_browser.py
docker exec CONTAINER python3 /work/capture.py /work/desktop.png
```

`npm run verify:linux` runs portable data and lifecycle checks on the host. It explicitly skips native Qt checks when PySide6 is absent; those skips do not establish native acceptance. The browser qualification uses disposable localhost pages and an explicit Chromium fake media device. It verifies actual remote isolation, permission denial, local cookie partitions, persistence, hidden-page sleep, and startup/lifecycle behavior. It never uses a real account or physical microphone.

A source launch needs distro PySide6 QtWidgets/QtNetwork/QtDBus, dbus-next, and the locked Electron distribution. Use `npm run start:linux` only when desktop interaction is authorized. Native launches create an app-owned autostart entry by default; the user can disable it in System. Development fixtures pass `--no-autostart` and store all data under their private `/work` directory.

## Data and integration

`~/.config/little-launcher/settings.json` retains the full launcher document. `linux.json` stores machine preferences separately. Browser sessions live under the private data directory's `browser/` tree. Profile changes retain previous partitions. Shortcut launchers belong to their creating OS through Platform. Legacy untagged shortcut launchers belong to Windows. Foreign launchers remain in the list disabled; supported launchers show/edit all items with no per-item OS controls. Web launchers are shared across systems. Missing local applications remain visible and explain failures when opened. Import merges launcher IDs and never removes unrelated local launchers. Export writes the full portable launcher envelope, including hidden rows and extension identities when known, without global credentials or browser sessions. The shared native item view also handles the regular editor, which matches the Windows 560 × 620 logical-pixel editor size and saves each edit immediately. The installed-application picker uses the XDG application catalog; extra arguments are never silently ignored for desktop entries.

Each launcher owns one StatusNotifierItem connection and native desktop menu. On KDE, System's explicit integration button installs only the app-owned user KWin helper. It positions mapped windows from activation coordinates, clamps them to the output work area, and preserves transient dialogs when dismissing web flyouts. It never queries a later pointer or repositions a returning parent. GNOME currently uses the labelled regular-window mode; GNOME anchored integration remains unfinished.

Ordinary hidden web pages freeze and later unload. Keep running starts without opening a window and retains background timers. Downloads, upload requests, audio, sign-in popups, and granted media access protect against automatic sleep/unload. Camera/microphone and screen-capture permission protects conservatively until document navigation or reload, including silent calls. Quit asks before interrupting protected activity. The real KDE portal source picker opens and preserves parent placement in the private fixture. The original GPU-free Debian fixture could not stream with QPainter. The Fedora 44 GPU fixture now receives real screen video through the KDE portal and blocks unconfirmed quit during capture. This verifies capture of the isolated virtual desktop, not the physical user session. Modern `WebHomeUrl` is independent of the bookmark collection. The native add-current-page dialog and bookmark folders preserve that separation. Right-click a bookmark for Windows-ordered navigation, rename/address, copy, home, move and removal actions. Ctrl/Shift/middle-click opens it in a new tab. Right-click an empty part of the bar to add an address or folder. Folder menus support rename, nested folder creation and Edit contents for their saved children. These actions keep unrendered entries and unknown metadata, reject stale menu/dialog saves, and return focus to the existing browser window. Rejected self/descendant moves cannot create folder cycles. Permission decisions are local to the running engine and are asked again after restart. Capture-ended precision, notification click routing, folder/overflow drag overlays, persisted favicon caching and physical drag acceptance and complete service workloads remain unfinished.

## Linux AppImage delivery

AppImage is the only offered Linux format. `linux/packaging/build.py` builds x64 on Debian 12 (glibc 2.36); the minimum target is Debian 12 / Ubuntu 24.04 LTS or newer. The image bundles private Python 3.11, PySide6-Essentials/Qt 6.11.2, dbus-next, Electron 45, Secret Service and Qt D-Bus client tools, and redistribution notices. Host graphics drivers, glibc and C++ runtime remain external. Source development continues to use distro Qt. A desktop Secret Service wallet is required for OneDrive; tokens never enter the image or settings.

```bash
npm ci --prefix linux/browser
npm run package:linux -- --engine-dir linux/browser/node_modules/electron/dist --output .artifacts/linux-appimage
chmod +x LittleLauncher-<version>-linux-x64.AppImage
./LittleLauncher-<version>-linux-x64.AppImage
```

The container receives source and engine read-only and assembles without network. The official type-2 runtime is size/hash locked in `runtime-lock.json`; changes require a reviewed lock update. Zstd payload extraction and relocated imports are checked. The private AppDir is a qualification intermediate, not another delivery format. No RPM/DEB builder is offered. ARM64 remains a future build target.

First production launch registers app-owned user menu entries/icon and enables login startup by default. System can turn startup off; that choice survives updates. Entries point at the stable AppImage file, never its temporary mount. Keep the image in its intended writable location. Preview setup stays disabled and never enables real startup. KWin helper installation remains an explicit System action.

About offers Check for Updates, Download, and Install and Restart. Automatic checks default on (after startup, then every six hours); downloads and installation require explicit actions. Only newer stable releases from the fixed GitHub repository, matching the exact platform asset name, declared size and SHA-256 digest, are accepted. Downloads are bounded and staged beside a writable, owned, nonsymlink AppImage. Installation waits for normal sync/browser shutdown, releases the instance lock, revalidates the payload and destination, retains `.AppImage.previous`, atomically replaces the image, then restarts with the same data directory. A declined protected-page quit cancels restart intent. Ordinary exit discards a staged download. Immediate execution failure restores the previous image; later startup crashes are not automatically detected. Source and read-only launches can check but cannot self-update. Check preference, startup, browser sessions and positions remain device-local.

The reusable `linux-appimage.yml` builds/extracts the image and checks bundled imports; `build-msix.yml` attaches AppImage and checksum alongside Windows assets. No workflow or release was published during local development. A private GPU-enabled Fedora KDE session verifies the real type-2 extract-and-run path, native Wayland, browser seccomp, default startup, stable menu entries, actual file replacement/restart, retained cookie/settings and startup-off choice. Replacement uses an identical payload with synthetic release metadata; it is not a live GitHub upgrade. FUSE mount mode and native Ubuntu desktop policy acceptance remain separate qualification work. The private Qt runtime does not load host KDE plugins across Qt ABIs; the packaged screenshot currently uses its fallback widget style. Full KDE theme-plugin fidelity remains a release gate, separate from the distro-Qt source preview.
