# Native Linux application

Read [the Linux architecture guide](../docs/linux.md) before changing this directory. Keep the portable JSON model independent of Qt. Native forms use Qt Widgets, standard layouts, and the desktop's palette, font, style, and dialog button order. Preserve Windows dimensions and section order where practical. Do not emulate Fluent controls with CSS.

Persistence and sync always use the full document. Shortcut launchers have whole-launcher Platform ownership; foreign launchers remain listed but disabled. Do not filter or classify individual items. Preserve their full original collections and dormant legacy metadata. Unknown properties must survive edits. Browser content runs in the current Electron engine with sandboxing and no Node access. Only trusted local chrome may use preload IPC. Never mount the host display, session bus, or personal browser profiles in the private KDE fixture.

For `sync.py`, `onedrive.py` and `portable_icons.py`, also read [sync.md](../docs/sync.md) and [icons.md](../docs/icons.md). Device-local enablement follows [user-settings.md](../docs/user-settings.md). Keep account tokens in Secret Service, never in settings, export or backups. Tests use synthetic account/network data; live sign-in acceptance is separate.

`sync_page.py` follows Windows `SyncPage.xaml` for provider/account/action layout; show unsupported destinations explicitly instead of adding nonfunctional controls. `web_preferences.py` is the trusted browser-setting allowlist. `browser/browser_identity.cjs` normally advertises the shipped Chromium version and retains Linux identity. The explicit user-requested compatibility experiment uses bare `Chrome` only on HTTPS accounts.google.com. The existing Chromium control channel applies it before the sign-in request and clears it before leaving; do not use setUserAgent inside network callbacks (it reloads the old page), or apply bare Chrome to Messages itself (HTTP400). Preview helpers must restrict both unique app identities and current launcher IDs, including after downloads. Treat real service/browser-profile acceptance separately from controlled fixtures.


For bookmark icon rendering (`browser/bookmark_icons.cjs`, `bookmarks.cjs` and trusted chrome), also read [icons.md](../docs/icons.md). Keep fetched icons bounded, credential-free and separate from synced source metadata; do not follow foreign bookmark file paths. Global icon-only mode must retain per-entry choices and accessible names.


`browser/tab_menu.cjs` follows Windows tab command order. Resolve actions by a still-live tab ID; background duplication must not select the new tab, and bulk closes must preserve per-tab interruption confirmation. Reopen history is bounded and in memory. Bookmark Set as home page must copy only the address and reject stale tree/home preimages. Navigation remains available on read-only subscriptions while mutations remain blocked.


`web_sessions.py` stores only device-local HTTP(S) tab addresses/selection; never add it to portable sync/export. Preserve unreadable session files and pending/live page state during teardown. Keep running restores all saved pages; other background pages may restore lazily. Explicit final-tab close clears only that launcher's session.

`browser_bookmarks.py` and `bookmark_picker.py` read bookmark sources only, never browser passwords/cookies, and support single selection and explicit multiple selection. Import commits retain full-source preimage/read-only checks. `LauncherDialog` applies completed controls immediately when attached to the controller; successful saves advance its preimage and stale forms must stop, not overwrite external changes.

For `browser/strip_drag.cjs`, trusted chrome drag events and `BookmarkTree.reorder`, read [drag-drop.md](../docs/drag-drop.md). Renderer drag state must originate internally; never trust an external MIME marker as ownership. Retain full saved paths, hidden entries and unknown metadata, and defer DOM rebuilds until drag completion.

For `external_drop.py` and native URI imports, also read [drag-drop.md](../docs/drag-drop.md): accept Copy/Link only, preserve internal session ownership and commit through full-source guards. For `icon_glyphs.py`, `icon_picker.py` and file-type/window icon rendering, read [icons.md](../docs/icons.md). Keep unsupported saved glyphs intact, pending Confirm/Cancel semantics and no bundled Windows fonts. Native theme refresh must deduplicate actual theme changes.

For `positions.py`, `anchor_picker.py` and fullscreen settings also read [user-settings.md](../docs/user-settings.md). Never copy Windows physical coordinates into Linux placement or sync Linux logical coordinates. Record actual KDE interactive moves only for enabled Last Position web launchers. QtDBus preview destinations must use the existing per-data-directory identity. For `bookmark_overlay*`, `bookmark_drag.js` and nested strip paths also read [drag-drop.md](../docs/drag-drop.md). Keep every local view's navigation locked and require a known trusted main frame before any IPC action. For fullscreen, keep temporary dimensions separate from saved size and cancel delayed fitting on navigation, resizing and disposal.

For `updates.py`, `update_controller.py`, `update_page.py` and `packaging/**`, read [installer.md](../docs/installer.md) and [versioning.md](../docs/versioning.md). AppImage is the only Linux delivery target (Debian12/Ubuntu24.04 minimum). Never replace a running image or bypass protected-page quit; retain strict size/hash/architecture/destination checks, stable startup paths and local preference boundaries. Build and qualification are isolated; no publishing or host setup is implied.

For `site_icon.py`, item icon rendering and `shortcut_import.py`, read [icons.md](../docs/icons.md) and [sync.md](../docs/sync.md). Public icon fetch is explicit/credential-free and Confirm-only; bulk bookmark import is a guarded full-document append. Native bookmark picking now supports explicit multiple selection as well as the original single-selection mode.

AppImage KDE appearance uses `packaging/host_bootstrap.py` only when the complete distro bindings/runtime and KDE platform plugin pass its probe. Never add host Qt plugin paths to bundled Qt, or remove the isolated bundled fallback. Qualify both launch paths after changing bootstrap selection.

Page-declared launcher icons may be WebP on a CDN (including WhatsApp). Electron nativeImage does not decode every such format on Linux; pass only bounded approved raster bytes to native Qt for validation/PNG normalization. Keep home-origin, navigation and pending-Confirm guards. Website icon selection must not introduce a second mode dropdown or offer item Composite for web launchers.

For `extension_packages.py`, `extensions_page.py`, `browser/extension_*`, `permission_store.cjs` and `browser/vendor/**`, read [the Linux extension boundary](../docs/linux.md#linux-site-permissions-and-extensions) and [user-settings.md](../docs/user-settings.md). Preserve per-session vault isolation, stable local packages and exact origin notification choices. Never grant transient capture permissions permanently, import external browser credentials, or expose app IPC/preload to ordinary pages. Vendor source provenance/licenses and reproducible compilation are part of the feature.

The service-worker notification compatibility preload is an app-owned standard-Web-API implementation, scoped by native worker identity, session, origin and existing notification permission. Its isolated transport exposes notification operations only; ordinary page views retain no app IPC/Node preload. Do not expand this exception to launcher/settings/files or replace site workers.

For `selfhst.py`, also read [icons.md](../docs/icons.md). Keep fixed public endpoints, bounded catalog/PNG validation, native desktop styling, reference-safe cache names, cancellation and latest-selection guards. Selected images and glyph previews use the portable icon boundary; never sync another device's file path as the only asset.

For `item_resize.py`, also read [drag-drop.md](../docs/drag-drop.md). Keep preview rendering detached from saved source, retain mouse capture across reflows, cancel on Escape/capture loss and commit only through the full-source stale/ownership guards. Wayland outer-window reanchoring must not feed back into pointer deltas.

For `browser/page_notifications.cjs` and worker notification activation, read [the Linux notification correction](../docs/linux.md#linux-notification-permission-and-activation-correction). The page CDP binding implements only standard Notification/Permissions APIs, removes its global immediately and authenticates actual native default execution context, current secure origin, live owner and saved profile grant. Never expose general app commands or trust a page-supplied origin/permission. Worker focus/open requires a real current notification-click task; no background auto-focus or unsafe schemes. Unknown notification state is default/prompt, never an automatic grant. Bootstrap renderer readiness must not freeze/unload a pending page, change saved tab state or introduce a Back entry. Keep Windows notification behavior unchanged.

Icon chooser layout follows [icons.md](../docs/icons.md#icon-chooser-layout-parity-follow-up): shared search above compact scrollable tabs, website/file choices in the first tab, native pinned Confirm/Cancel and pending-only previews. Preserve complete Unicode, per-symbol color, controlled selfh.st preselection, bounded thumbnail work and Cancel semantics; do not bundle Windows fonts or advertise the complete Fluent catalog. `dev/verify_icon_chooser_layout.py` uses synthetic data in the private compositor.

Manual sync review follows [sync.md](../docs/sync.md#manual-icon-upload-cloud-revisions-and-collapsed-destinations). Compare content to the successful baseline, not just OneDrive ETags. Prepare before the single confirmation, bind review to exact local bytes/revision and cloud revision/content, preserve Cancel and compatibility gates, and back up replaced cloud data. Never choose a side automatically when both complete documents changed. `dev/verify_sync_review.py` uses synthetic accounts and an in-memory cloud only. Destination expansion must not change enablement/account state.
